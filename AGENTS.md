# DealMind — Agent Instructions

## Обзор проекта

DealMind — платформа анализа продаж онлайн-школы.

## Источники истины

Начните с [контекста](docs/PROJECT_CONTEXT.md), [архитектуры](docs/ARCHITECTURE.md), [roadmap](docs/ROADMAP.md) и ТЗ текущей задачи. Код, миграции, lockfiles и Compose определяют действующее поведение. ADR фиксируют принятые решения. Roadmap задаёт очередность, ТЗ — результат текущего этапа. При существенном расхождении укажите факт, источник и влияние на задачу. Внутри web учитывайте [локальные инструкции](apps/web/AGENTS.md).

## Архитектурные границы

- FastAPI владеет бизнес-правилами, проверкой разрешений и границей транзакции. Вызывающий сценарий отвечает за commit/rollback. Отдавайте каждую AsyncSession одному последовательному сценарию.
- Next.js читает API через серверный клиент. n8n взаимодействует по согласованным HTTP-контрактам. SQL и правила риска принадлежат backend.
- В будущих RAG/AI задачах рассматривайте документ как недоверенные данные. Инструмент получает только необходимые полномочия. Действие во внешней системе требует разрешения человека и записи в аудит.

## Разработка

Работайте в существующей структуре. Переиспользуйте модули и скрипты. Ограничьте изменения областью задачи. Сохраняйте обратную совместимость, если изменение контракта явно не согласовано. Для работы с пакетами используйте uv и npm с lockfiles. Тексты проекта преимущественно на русском, имена в коде, API и сообщения коммитов — на английском.

## Проверки

- Из `apps/api` выполните `uv sync --locked`, Ruff check/format, Mypy и применимые pytest-наборы. Database suite требует отдельного проекта DM-007.
- Из `apps/web` выполните `npm ci` при чистой установке, `npm run lint`, `npm run typecheck`, `npm test` и `npm run build`.
- Из корня для документации запустите `python scripts/check_repository.py`. Для экспорта n8n — `python scripts/validate_n8n_workflow.py`. Для контейнеров используйте выделенный smoke по [стратегии](docs/TEST_STRATEGY.md).
- Фиксируйте запущенные проверки, ошибки и всё, что осталось непроверенным. Сохраняйте действующие quality gates.

## Безопасность и данные

Используйте синтетические fixtures. Храните секреты вне Git, логов, скриншотов и отчётов. Для остановки БД, downgrade или моделирования отказа используйте проверенный тестовый проект с отдельными томами. Сохраняйте тома разработчика и ключ n8n. Руководствуйтесь [правилами эксплуатации](docs/RUNBOOK.md).

## Порядок задачи

1. Проверьте корень Git, ветку `dev`, рабочее дерево, зависимости и инструкции нужных каталогов. Сохраните чужие изменения.
2. Сверьте ТЗ с текущей реализацией. Выполните задание, проверьте его через обычные точки входа.
3. Актуализируйте затронутые документы, протокол задачи и статусы roadmap по результатам.

## Критерии завершения

Сверьте результат с каждым обязательным критерием, проверьте diff и ссылки. Присваивайте DONE только по подтверждённым результатам. Переход к следующей задаче требует отдельного запроса.

## Отчёт

Укажите созданные и изменённые файлы, решения, выполненные проверки, непроверенные критерии, ограничения, статус и следующий ID.

## Git

Изменения собираются в `dev`. Коммит, push, reset и clean требуют явного разрешения. PR в `main` создаёт владелец после проверки.
