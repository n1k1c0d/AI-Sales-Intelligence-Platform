# DealMind · n8n Integration Layer

n8n будет принимать webhooks, запускать проверки по расписанию и доставлять разрешённые уведомления. Для получения данных, регистрации события и возврата результата workflow обращается к FastAPI. Backend рассчитывает риск, проверяет полномочия и владеет доменными таблицами. [Границы интеграций](../../docs/ARCHITECTURE.md)

## Как версионировать workflow

- Один workflow решает одну задачу. Для экспортов используется каталог `workflows/` и имя в kebab-case, описывающее действие. Пример будущего имени — `check-api-health.json`.
- Рядом с экспортом документируются триггер, вход, ожидаемый результат, вызываемый API и поведение при ошибке. Для повторно доставляемых событий указывается ключ идемпотентности. В `examples/` допустимы только синтетические примеры.
- Перед публикацией JSON проверяют на credentials, токены, заголовки авторизации, личные адреса и сохранённые данные запусков. Credentials настраиваются в локальном n8n отдельно от экспорта.
- Для каждого будущего workflow проверка поставки включает экспорт JSON, импорт в чистый локальный n8n, привязку credentials и повтор контрольного события. В документации фиксируют результат успешного и ошибочного запусков.
