# Демонстрационные сценарии

Текущие сценарии используют локальный технический стенд и синтетические данные. Перед показом проверьте ветку, порты и состояние сервисов. Для каждого сценария ниже указаны цель, польза, компоненты, шаги, ожидаемый результат и границы фактической проверки. Команды для Docker выполняются из корня. [Runbook](RUNBOOK.md)

## PHASE 0 · доступно сейчас

| ID и цель | Польза и предусловия | Шаги и ожидаемый результат | Фактическая проверка и ограничения |
| --- | --- | --- | --- |
| DEMO-001 · Запуск PHASE 0 | Разработчик получает повторяемый стенд. Нужны Docker, .env и образы | Выполните Quick Start, проверьте `docker compose ps` и `bash scripts/smoke_infra.sh`. Ожидаются четыре healthy-сервиса и пройденные HTTP/SQL-проверки | PASS на выделенном Compose-проекте DM-011. Полный fresh clone относится к DM-012 |
| DEMO-002 · Backend API | Интегратор может проверить контракт. Нужен FastAPI | Откройте /docs, выполните GET health и ready, сопоставьте заголовок X-Request-ID с событием в логах | PASS по живому OpenAPI и ответам DM-011. Readiness зависит от БД |
| DEMO-003 · PostgreSQL | Оператор отличает работающий HTTP-процесс от доступной БД. Нужны api и db | Проверьте readiness, выполните alembic current и heads, запросите pg_extension. После upgrade ожидаются database ok, head 0002 и vector 0.8.7 | В DM-011 проверялась baseline 0001. Текущая ревизия с восемью CRM-таблицами проверена в [DM-102](tasks/DM-102.md) |
| DEMO-004 · System Overview | Пользователь видит результат обеих проб. Нужны web, api и db | Откройте /, нажмите Refresh Status, проверьте время, статусы и разные Request IDs. При доступном API и БД ожидается operational | Визуальная приёмка DM-008, реальные BFF и shell страницы и 29 frontend-тестов в DM-011. Обновление запускается по запросу |
| DEMO-005 · n8n System Health Check | Инженер находит запрос по отчёту исполнения. Нужны редактор n8n, импортированный граф, api и db | Выполните Manual Trigger, откройте последний узел в Executions. Сверьте один итоговый JSON и два ID с логами API | Реальные UI/CLI-проверки DM-009/010. В DM-011 повторены валидатор и smoke. Отчёт описывает момент проверки |
| DEMO-006 · Отказ и восстановление БД | Оператор видит причину деградации и проверяет восстановление. Только выделенные тестовые проекты | Из корня `python scripts/ci_stack.py n8n` покажет operational и degraded при остановке тестовой БД, health 200, ready 503. Затем на отдельной БД DM-007 запустите из apps/api `uv run --locked pytest -m database -k recovery_without_app_restart` — та же FastAPI возвращается к ready после запуска БД | PASS в database-integration и n8n-validation на f08b53c. Две проверки используют отдельные проекты; остановку основной db для показа не выполняют |
| DEMO-007 · CI Gate | Ревьюер проверяет конкретную версию до merge. Требуется доступ к репозиторию GitHub | Откройте подтверждённый run, сверьте dev и SHA, затем backend-quality, database-integration, frontend-quality, n8n-validation и общий gate. Откройте Artifacts | Семь успешных jobs, пять артефактов на f08b53c. Артефакты имеют срок хранения семь дней |
