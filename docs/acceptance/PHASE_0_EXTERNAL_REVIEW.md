## GitHub Actions и граница проверки

В workflow присутствуют `repository-checks`, `backend-quality`, `database-integration`, `frontend-quality`, `n8n-validation`, `docker-smoke` и `ci-gate`. Итоговый job **CI Gate** зависит от всех шести проверок через `needs`. Он выполняется с `always()` и возвращает ошибку, если любой результат отличается от `success`. На GitHub для исходного коммита `035fb35` есть завершившийся успешный запуск. Для публикации текущих исправлений требуется новый запуск на получившемся SHA. После публикации исправлений и успешного CI скопируйте полный SHA из запуска GitHub Actions и подставьте его в `<SHA>`. Из корня репозитория выполните:

```shell
git ls-tree -r --name-only <SHA>
git archive --format=zip --output=../dealmind-phase0-review.zip <SHA>
```
