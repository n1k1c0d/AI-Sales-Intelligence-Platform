## Цель

Дать каждой части DealMind постоянный путь от корня Git, описать её границы и задать общие правила хранения и форматирования файлов. Разработчик должен иметь возможность начать настройку Python в `apps/api/` без переноса каталогов.

## Контекст

До работы в чистой ветке `dev` корневой README и документы DM-001 уже находились на своих местах. Вложенный каталог `dealmind/` содержал мастер-спецификацию и 12 отслеживаемых файлов .gitkeep. Вложенных репозиториев и файла LICENSE не обнаружено. Каркас подлежал переносу на уровень корня Git вместе с существующими вложенными каталогами.

## Зависимости

DM-001 принята. При реорганизации действуют границы модульного монолита и n8n Integration Layer. Разработка ведётся в `dev`, pull request в `main` открывает автор после проверки. [Архитектура](../ARCHITECTURE.md) · [ADR-0001](../adr/0001-modular-monolith.md)

## Объём работ

Перенести существующий каркас, объединить документацию в `docs/`, создать README для шести областей, настроить корневые Git ignore и EditorConfig. Скорректировать пути, статус задачи и ссылки в документах DM-001.

## За пределами задачи

Настройка Python, Node.js, БД, Docker Compose, n8n и CI выполняется в последующих задачах. Генерация данных и разработка исходного кода также запланированы отдельно. Выбор лицензии относится к решениям владельца проекта.

## Последовательность работ

1. Сверить ветку, состояние дерева, Git-корень, вложенные репозитории и прочитать документы DM-001.
2. Перенести существующие файлы в целевые каталоги с проверкой коллизий. Обновить ссылки на мастер-спецификацию.
3. Описать области, задать Git ignore и EditorConfig, актуализировать корневой README и контекст.
4. Проверить дерево, правила, ссылки и изменения. После приёмки выставить DM-002 — DONE и DM-003 — READY.

## Проверка

Проверки выполняются из корня Git. Для правил игнорирования достаточно передать Git имена предполагаемых файлов, создавать их для проверки не требуется.

```powershell
git branch --show-current
git status --short --untracked-files=all
git diff --check
git diff --stat
git diff --cached --stat
git check-ignore --no-index -q -- apps/api/.env.local
git check-ignore --no-index -q -- apps/api/uv.lock
```

В двух последних командах ожидаются коды 0 и 1 соответственно. Проверяются также локальные БД и экспорты, артефакты сборки, пример окружения, миграции, данные демо и workflow JSON. Существование относительных ссылок проверяется от каталога каждого документа. Содержимое новых файлов проверяется отдельно от вывода diff. Для перенесённых файлов сравниваются Git-хеши с исходными объектами в HEAD.
