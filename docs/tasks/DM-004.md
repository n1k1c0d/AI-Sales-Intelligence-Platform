# DM-004 · FastAPI Application Bootstrap & HTTP API Foundation

**Task ID** DM-004 · **Этап** PHASE 0 · **Приоритет** P0 · **Версия ТЗ** 1.0

## Цель и зависимости

Предоставить первый доступный по HTTP интерфейс DealMind и проверить его на уровне ASGI и реального сервера. Основа — архитектура DM-001, структура DM-002 и Python-пакет DM-003. Перед изменениями на чистой ветке `dev` проверены lock-файл, импорт, версия distribution, оба прежних теста, Ruff и Mypy. [DM-003](DM-003.md)

## Объём и границы работ

Задача включает фабрику FastAPI, entrypoint для Uvicorn, системные маршруты, lifespan, DI, схемы Pydantic v2, централизованные ошибки, Swagger UI и HTTP-тесты. Подключение БД, контейнеры, конфигурация окружений, аутентификация, CRM, n8n и AI относятся к последующим этапам.

## Шаги реализации

1. Добавить runtime-зависимости и HTTPX через uv, зафиксировать разрешение в lock-файле.
2. Инициализировать в фабрике состояние готовности каждого приложения. Во время lifespan переводить его в готовность и сбрасывать при shutdown.
3. Подключить версии маршрутов через общий router. Вынести определение готовности в FastAPI Depends и описать успешный и неуспешный ответы одной моделью.
4. Зарегистрировать обработчики Starlette HTTPException, ошибок валидации и неожиданных исключений. Возвращать безопасные структурированные детали и сохранять HTTP-статус и служебные заголовки.
5. Прогнать TestClient, статические проверки и сборку, запустить Uvicorn на loopback-интерфейсе и проверить ответы через curl и браузер.

## Контракты API

| Запрос | HTTP | Тело |
| --- | --- | --- |
| GET `/api/v1/health` | 200 | `{"status":"ok","service":"dealmind-api"}` |
| GET `/api/v1/ready` после startup | 200 | `{"status":"ready","checks":{"application":"ok"}}` |
| GET `/api/v1/ready` при неготовности | 503 | `{"status":"not_ready","checks":{"application":"not_ready"}}` |
| GET `/openapi.json` | 200 | Схема с обоими GET, моделями и описаниями ответов |
| GET `/docs` | 200 | Swagger UI, группа System |

Ошибки имеют конверт `error` с полями `code`, `message` и `details`. Для 404, 405, 422 и 500 определены коды NOT_FOUND, METHOD_NOT_ALLOWED, VALIDATION_ERROR и INTERNAL_SERVER_ERROR соответственно. В 422 поле `details` содержит список элементов с `loc`, `message` и `type`. Для 500 поле равно null, текст сообщения фиксирован. При иных HTTP-исключениях сохраняется код HTTP и возвращается безопасное описание HTTP_ERROR.

## Известные ограничения

Readiness отражает готовность приложения. Доступность PostgreSQL будет проверяться после подключения в DM-007. Swagger UI использует ресурсы CDN. Starlette 1.10.0 предупреждает о будущем прекращении поддержки HTTPX 0.x в TestClient. HTTPX 0.28.1 оставлен согласно ТЗ, предупреждение видно при запуске тестов. Во время приёмки порт 8000 был занят, поэтому curl и Edge проверяли тот же сервер на 127.0.0.1:8001. Тестовый сервер после проверки остановлен.
