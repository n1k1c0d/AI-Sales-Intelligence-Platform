## 4. Контракт конфигурации

`create_app(settings=None)` загружает одну frozen-модель из процесса либо принимает готовую модель. `Depends(get_settings)` возвращает объект из `app.state.settings`. Основные значения перечислены ниже.

| Параметр | Default | Валидация |
| --- | --- | --- |
| APP_ENV | local | local, test, production |
| APP_LOG_LEVEL | INFO | DEBUG, INFO, WARNING, ERROR, CRITICAL |
| APP_CORS_ORIGINS | [] | JSON-массив отдельных HTTP(S) origins, преобразуется в неизменяемый tuple |

Приложение не ищет dotenv в текущем каталоге. В Compose переменные явно передаются сервису `api`. Пустое или неверное значение известной переменной диагностируется при создании настроек. [Примеры и команды](../../apps/api/README.md#configuration--logging)

## 5. Контракт логов

Прикладной logger пишет JSON в stderr. Поля события включаются по разрешённому списку. Ниже запись фактического запроса при проверке контейнера.

```json
{"timestamp":"2026-11-24T10:33:31.040Z","level":"INFO","logger":"dealmind.api","message":"HTTP request completed","service":"dealmind-api","environment":"local","request_id":"8d64c301-700c-4f1b-9fad-1c645975ba70","event":"http.request.completed","http_method":"GET","http_route":"/api/v1/health","status_code":200,"duration_ms":0.832}
```

Ошибка формирует событие `http.request.failed` с типом исключения, безопасным сообщением, шаблоном маршрута и фактическим статусом. У необработанного пути применяется метка `<unmatched>`. Тела, query, cookies, Authorization и текст исключения не записываются. На INFO и DEBUG видны completion-события. При WARNING и выше такие события фильтруются.

## 6. Контракт Request ID

Один входной UUID v4 принимается в канонической или компактной форме и возвращается в канонической записи. При отсутствии, дублировании или неверном значении создаётся UUID v4. Идентификатор хранится в ContextVar, попадает в заголовок `X-Request-ID` и прикладные логи. Контекст восстанавливается по token, в том числе при ошибке.

## 7. Middleware и обработка исключений

Порядок обработки — RequestContextMiddleware → CORSMiddleware → FastAPI с существующими обработчиками ошибок и router. Обёртка вокруг полного стека устанавливает ID на `http.response.start`, включая 500 и OPTIONS. Отсчёт длительности ведётся через `perf_counter()`. Части потокового ответа передаются без накопления. Если поток оборвался до конца, фиксируется событие ошибки с уже отправленным статусом. Для полностью переданного ответа возникает одно событие завершения. [Архитектура](../ARCHITECTURE.md#13-наблюдаемость)

## 8. CORS

Разрешение выдаётся только origin из модели. Методам GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS доступны Content-Type, Authorization, X-Request-ID. Разрешённый браузерный клиент может прочитать ID из ответа. Credentials отключены. Возможность схемы HTTPS в allowlist относится к адресам клиентов. Привязки Docker к loopback сохраняются.
