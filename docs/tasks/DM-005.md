## 2. Инфраструктура и окружение

Три сервиса работают в проекте `dealmind` на одной bridge-сети `dealmind_dealmind-network`. API запускает ASGI-приложение DM-004. База хранит данные в `dealmind_postgres_data`. Редактор n8n использует свою SQLite и настройки в `dealmind_n8n_data`. У каждого сервиса свой health check и политика перезапуска `unless-stopped`. [Схема и зависимости](../ARCHITECTURE.md#14-развёртывание)

| Переменные | Значение по умолчанию или назначение |
| --- | --- |
| `COMPOSE_PROJECT_NAME` | `dealmind`, префикс контейнеров, сети и томов |
| `API_HOST_PORT`, `POSTGRES_HOST_PORT`, `N8N_HOST_PORT` | `8000`, `5433`, `5678` на loopback хоста |
| `POSTGRES_DB`, `POSTGRES_USER` | База и начальная роль `dealmind` |
| `POSTGRES_PASSWORD`, `N8N_ENCRYPTION_KEY` | Обязательные независимые локальные секреты. Поля в шаблоне пустые. |
| `GENERIC_TIMEZONE`, `TZ` | `UTC` для n8n |

Внутри сети работают адреса `api:8000`, `db:5432`, `n8n:5678`. Compose формирует адрес редактора и webhook n8n из фактического порта хоста. [Настройка окружения](../../README.md#local-development-with-docker)

## 7. Проверка API

С хоста `/api/v1/health` вернул HTTP 200 и `{"status":"ok","service":"dealmind-api"}`. Ответ `/api/v1/ready` — HTTP 200 и `{"status":"ready","checks":{"application":"ok"}}`. OpenAPI содержит оба GET. В браузере Edge Swagger отобразил оба маршрута. Изнутри контейнера HTTP-доступность проверяет собственный health check.

## 8. Проверка PostgreSQL

SQL-клиент установил TCP-соединение с базой `dealmind` под ролью `dealmind`. Команда `SELECT 1` вернула `1`, версия сервера — `17.12`. Каталог `pg_extension` вернул `vector | 0.8.7`. Для `[1,0,0]` и `[0,1,0]` оператор евклидова расстояния `<->` вернул `1.4142135623730951`. Порт 5433 на хосте также ответил по протоколу PostgreSQL.

## 9. Проверка n8n и постоянных данных

В браузере открылась страница `/setup` с полями email и пароля владельца. Завершение регистрации остаётся владельцу локального экземпляра. HTTP readiness вернул 200. Node.js внутри n8n получил по адресу `http://api:8000/api/v1/health` корректный ответ приложения.

Для проверки томов созданы уникальная таблица PostgreSQL с контрольной строкой и файл-маркер в томе n8n. После `docker compose -p dealmind down` контейнеров проекта осталось ноль, оба тома существовали. После повторного запуска у трёх контейнеров сменились ID. Проверены имена и точки подключения исходных томов, значение строки и содержимое маркера. Также подтверждены совпадение контрольной суммы конфигурации n8n и наличие непустой SQLite. Тестовые таблица и файл удалены, после чего повторён smoke-тест.

## 12. Безопасность

В Git доступен шаблон с пустыми полями. Обе сгенерированные строки проверены на отсутствие в файлах рабочего дерева, доступных Git. Проверка Docker inspect ограничена состоянием, сетью, портами и точками монтирования. В API отсутствуют секреты других сервисов. Init-каталог PostgreSQL смонтирован только для чтения. Полный вывод развёрнутой конфигурации с секретами в отчёт не включается.

## 14. Ограничения и диагностика

- n8n сообщает об отсутствии Python 3 для необязательного внутреннего Python task runner. Редактор, SQLite, readiness и HTTP-связь с API работают. Выполнение Python-кода внутри workflow выходит за объём DM-005.
- Pytest выдаёт одно исходное предупреждение Starlette о связке TestClient с HTTPX. Все 15 тестов проходят.
- Локальный HTTP рассчитан на loopback. При первом входе в редактор владелец вводит свои данные. Для проверки подключения API к БД предусмотрена отдельная задача.
