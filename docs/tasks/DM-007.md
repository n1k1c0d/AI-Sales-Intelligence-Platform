# DM-007 · Асинхронный доступ к PostgreSQL и миграции Alembic

## 1. Задача и результат

DM-007, PHASE 0. Исходная ветка `dev` на коммите `95af29c` содержала принятые DM-001…006. До изменений прошли 46 тестов, Ruff, Mypy и проверка lockfile. Цель — обеспечить приложению асинхронное соединение, транзакции, версионирование схемы и проверяемую готовность к работе с данными. Реализация охватывает backend, Docker и тестовую БД. Предметная модель CRM, CRUD, frontend и автоматизации относятся к другим этапам.

## 2. Зависимости

На Python 3.12.13 с uv 0.11.0 разрешены SQLAlchemy 2.1.9 с asyncio, Psycopg 3.3.9 с binary, Alembic 1.20.1 и pytest-asyncio 1.5.0 для тестов. Версии сохранены в `uv.lock`.

## 3. Database Architecture

У каждого lifespan собственный AsyncEngine с пулом и pre-ping, фабрика AsyncSession и объект проверки БД. DI `get_db_session` выдаёт отдельную сессию операции, а выход из контекста закрывает её. Application service владеет транзакцией и может использовать `async with session.begin()`. Репозиториям делегируются операции и flush. После ошибки незавершённые записи откатываются. При shutdown вызывается `engine.dispose()`. У общего Declarative Base задана схема именования PK, FK, UQ, CHECK и индексов. [ADR-0002](../adr/0002-async-database-access.md)

## 5. Settings Contract

| Переменная | Локальный default | Назначение |
| --- | --- | --- |
| APP_DB_HOST / APP_DB_PORT | 127.0.0.1 / 5433 | Адрес PostgreSQL с хоста. В Compose используется db:5432. |
| APP_DB_NAME / APP_DB_USER | dealmind / dealmind | База и роль |
| APP_DB_PASSWORD | отсутствует | SecretStr, Compose передаёт существующий POSTGRES_PASSWORD |
| APP_DB_POOL_SIZE / APP_DB_MAX_OVERFLOW | 5 / 5 | Базовый размер пула и дополнительные подключения |
| APP_DB_POOL_TIMEOUT / APP_DB_CONNECT_TIMEOUT | 5 с / 3 с | Ожидание пула и установления соединения |
| APP_DB_HEALTH_TIMEOUT | 5 с | Общий предел проверки от получения соединения до результата SELECT 1 |

В production пять полей подключения задаются явно. В local/test пропущенный пароль допускает запуск. Ошибочно заданные значения отклоняются при валидации. Для CLI и приложения используется общий объект SQLAlchemy URL. [Конфигурация и диагностика](../../apps/api/README.md#database-architecture)

## 6. Migration Results

Единственная head — `0001`. Основная БД `dealmind` на PostgreSQL 17.12 уже имела vector 0.8.7. Отдельный запуск в Docker применил baseline, `current` и таблица версий подтвердили `0001`. В public появилась одна служебная таблица `alembic_version`. На свежей отдельной тестовой БД проверены установка расширения, повторный upgrade, отсутствие расхождений metadata, downgrade и повторное обновление. При downgrade расширение сохранилось. Offline-режим сформировал SQL без подключения. Миграции выполняются отдельной командой до обновления API.

## 7. API Contracts

| Сценарий | HTTP | JSON body |
| --- | --- | --- |
| Живой процесс, GET /api/v1/health | 200 | `{"status":"ok","service":"dealmind-api"}` |
| Startup завершён, PostgreSQL отвечает | 200 | `{"status":"ready","checks":{"application":"ok","database":"ok"}}` |
| БД недоступна или отсутствует пароль | 503 | `{"status":"not_ready","checks":{"application":"ok","database":"not_ready"}}` |
| Lifespan ещё не готов | 503 | `{"status":"not_ready","checks":{"application":"not_ready","database":"not_ready"}}` |

Заголовок X-Request-ID сохраняется для всех этих состояний. Отдельный вызов сессии при недоступной БД получает безопасный ErrorResponse с кодом DATABASE_UNAVAILABLE.

## 12. Безопасность и сохранность данных

Пароль хранится в локальном окружении и передаётся драйверу через URL.create. Параметры SQL скрыты в диагностике engine. События приложения содержат безопасные имена и статусы. Хост-порты опубликованы на loopback. Тестовая конфигурация использует отдельные демонстрационные credentials. Перед записью проверяются имя БД, опубликованный порт, Docker labels, том и идентификатор кластера, полученный с обеих сторон подключения. Дополнительно проверен отказ тестового набора при подстановке имени основной БД. Временные объекты создаются только после этих проверок и удаляются в finally.

## 15. Известные ограничения

Настройки пула — исходные значения для разработки. Производственные лимиты и права ролей потребуют отдельной настройки. Readiness подтверждает выполнение SQL, текущая ревизия проверяется отдельно. На Windows асинхронному Psycopg требуется selector event loop. В HTTP-тестах сохраняется прежнее предупреждение Starlette о TestClient и HTTPX.
