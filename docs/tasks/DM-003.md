# DM-003 · Python Environment, Package Structure & Quality Tools

**Task ID** DM-003 · **Этап** PHASE 0 — Project Foundation · **Приоритет** P0 · **Версия ТЗ** 1.0

## Цель и зависимости

Подготовить устанавливаемый Python-пакет в `apps/api/`, чтобы DM-004 могла добавить FastAPI поверх уже проверенной упаковки. Исходные условия — принятые архитектурные границы DM-001 и структура monorepo из DM-002. Перед работой проверены ветка `dev`, чистое рабочее дерево, документы DM-001/002 и отсутствие существующего Python-проекта. [Архитектура](../ARCHITECTURE.md) · [DM-002](DM-002.md)

## Объём работ

Python 3.12, отдельный uv-проект, src-layout, PEP 517 build backend, dev-группа, тесты импорта и метаданных, статические проверки, сборка и документация. HTTP-приложение, доменные сервисы, БД, Docker, CI, n8n, frontend и AI-интеграции относятся к следующим задачам.

## Структура и конфигурация

| Путь от `apps/api/` | Роль |
| --- | --- |
| `.python-version`, `pyproject.toml` | Локальный Python 3.12, совместимость `>=3.12`, метаданные distribution и настройки инструментов |
| `src/dealmind/__init__.py`, `src/dealmind/py.typed` | Импортируемый пакет и маркер типизации для потребителя wheel |
| `tests/unit/test_package_import.py` | Два smoke-теста для пакета и его установленных метаданных |
| `uv.lock` | Версии и хеши зависимостей из PyPI |
| `README.md` | Рабочий процесс разработчика от установки до сборки |

Начальная distribution — `dealmind-api` версии `0.1.0`. Runtime-зависимости пусты. Hatchling собирает sdist и wheel. Ruff настроен на Python 3.12, строку в 100 символов и группы E4, E7, E9, F, I, B, UP. Mypy проверяет `src` и `tests` в strict-режиме. pytest ищет тесты в `tests/` и проверяет корректность маркеров и конфигурации.

## Шаги реализации

1. Проверить действующие версию uv и доступность интерпретатора Python 3.12 через uv.
2. Создать пакет, маркер типизации, метаданные, конфигурацию инструментов и два smoke-теста.
3. Выполнить `uv add --dev ruff mypy pytest`, синхронизировать окружение и проверить актуальность lock-файла.
4. Собрать sdist и wheel. Проверить содержимое архивов и установить wheel отдельно от дерева исходников.
5. Воспроизвести установку с нуля по lock-файлу, проверить Git ignore, документацию и итоговый состав изменений.

## Проверка и результаты

Проверено на Windows x64, CPython **3.12.13**, uv **0.11.0**. В проектном окружении установлены Ruff **0.17.6**, Mypy **2.4.1** и pytest **9.2.0**. Из корня monorepo сначала перейдите в `apps/api/`. [Полные команды разработчика](../../apps/api/README.md)

| Команда или проверка | Результат |
| --- | --- |
| `uv sync`, `uv lock --check`, `uv sync --locked` | PASS. Повторная синхронизация сохранила содержимое manifest и lock-файла. |
| `uv run --locked pytest` | PASS. Обнаружены и пройдены два теста. |
| `uv run --locked ruff check .`, `uv run --locked ruff format --check .` | PASS. Замечаний и изменений форматирования нет. |
| `uv run --locked mypy src tests` | PASS. Проверены два Python-файла в strict-режиме. |
| Импорт через `uv run --locked python` | PASS. В editable-окружении путь ведёт в `src/dealmind/__init__.py`, метаданные возвращают версию 0.1.0. |
| `uv build` | PASS. Собраны sdist и wheel. В wheel есть `dealmind/__init__.py` и `dealmind/py.typed`, внешние runtime-требования отсутствуют. |

В чистой временной копии из файлов проекта с пустым окружением выполнены `uv sync --locked`, проверка lock-файла, pytest, обе проверки Ruff, Mypy и изолированный импорт. Для этой проверки uv работал офлайн с уже заполненным кешем. Содержимое `uv.lock` и `pyproject.toml` не изменилось.

Отдельно wheel установлен в новое окружение через `uv pip install --no-index --no-deps`. Интерпретатор с флагом `-I` загрузил пакет из этого окружения и прочитал маркер `py.typed` и версию. Это проверяет поставляемый артефакт независимо от editable-установки.
