## 5. AGENTS.md

Указаны источники истины, вложенные правила Next.js, границы FastAPI, PostgreSQL, web и n8n, команды для применимых проверок и работа с синтетическими данными. AGENTS закрепляет работу в dev, владение PR пользователем и явное разрешение на commit/push. При завершении агент сверяет критерии и фиксирует непроверенное.

## 6. Architecture Documentation

Текущий контур описывает вызовы из web и n8n к FastAPI и запрос API в PostgreSQL. Диаграмма контейнеров показывает bridge-сеть, внутренние и опубликованные порты, SQL-том и SQLite n8n. Отдельный раздел MVP показывает CRM ingestion, Risk Engine, поиск знаний, LangGraph, согласование человеком и только затем исполнение внешнего действия. Будущие repositories и application services обозначены в модели целевой архитектуры.

## 7. Data Model

В работающей БД подтверждены единственная таблица в public `alembic_version`, revision `0001` и pgvector 0.8.7. Модель предлагает 16 сущностей для CRM, знаний, рисков, AI и аудита. Поля Deal и Activity, связи и гипотезы о кардинальностях вынесены в отдельный справочник. Правила reopening, признание выручки, валюты и бизнес-дата остаются открытыми для PHASE 1.

## 8. API Contracts

С рабочего FastAPI считан /openapi.json. В нём два GET-маршрута, обе схемы 200, схема ready 503 и ErrorResponse для 422/500. Проверены живые ответы backend и frontend, независимые ID двух проб и correlation запроса с реальным логом API. Автоматические HTTP-тесты подтвердили поведение при 404, 405, 422, 500, неготовом lifecycle и отказе зависимости. В документе различаются технический web health, SQL-readiness и агрегированный BFF.

## 9. Operational Runbook

Описаны требования для Docker-only и разработки на хосте, безопасная настройка .env, сборка, очередь запуска, миграции, обслуживание и остановка. Справочник окружения сверяет переменные с шаблоном, Compose, Settings, серверным frontend, CI и test fixtures. В таблице troubleshooting для 15 симптомов даны проверка, безопасное действие и условие остановки. Отдельно описаны перенос каталога, другой Docker Engine, backup PostgreSQL, том n8n, JSON экспорт и encryption key.

## 10. Demo Scenarios

DEMO-001–007 используют текущий стек. Для каждого указаны цель, польза, компоненты, шаги, ожидаемый результат, источник фактической проверки и ограничение. Сценарий восстановления использует отдельные тестовые проекты. DEMO-101, 102, 201, 301, 401 имеют статус PLANNED и описывают будущую аналитику, риски, уведомления, RAG и AI Deal Analyst.
