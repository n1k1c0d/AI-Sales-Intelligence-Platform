# Демонстрационный CRM-датасет DealMind

Генератор создаёт одну вымышленную онлайн-школу с воронкой от заявки до покупки или отказа. Набор служит эталоном для проверки запросов, истории переходов и будущих правил риска. Фамилии и телефоны из CRM не используются. Имена имеют вид «Учащийся Академии 0001», почтовые адреса оканчиваются на `@example.invalid`, телефоны получают NULL. [Фактический manifest](dataset-manifest.json) · [Приёмка DM-103](../../docs/tasks/DM-103.md)

## Предпросмотр без PostgreSQL

Из корня репозитория в PowerShell путь к Python-проекту задаёт флаг `--project`.

```powershell
uv run --project .\apps\api --locked python -m dealmind.demo.cli generate --dry-run
```

Из `apps/api` выполните следующие команды. Первый запуск печатает JSON, второй также сохраняет читаемый UTF-8 manifest. Укажите другой путь для экспериментальной конфигурации.

```shell
uv sync --locked
uv run --locked python -m dealmind.demo.cli generate --dry-run
uv run --locked python -m dealmind.demo.cli generate --dry-run --manifest ../../data/demo/dataset-manifest.json
uv run --locked python -m json.tool ../../data/demo/dataset-manifest.json
uv run --locked python -m dealmind.demo.cli generate --help
```

| Параметр CLI | Значение по умолчанию | Что определяет |
| --- | --- | --- |
| `--seed`, `--anchor-date` | 42, `2026-11-26T00:00:00Z` | Локальный Random и момент наблюдения. У времени обязателен UTC offset |
| `--history-days` | 180 | Окно создания возможностей. Минимум 28 дней для контрольных повторных покупок |
| `--contacts`, `--deals` | 600, 800 | Размер базы и число отдельных возможностей. Минимум четыре контакта для независимых примеров повторных и одиночных обращений |
| `--managers`, `--sales-leads` | 8, 1 | Размер команды. Каждый менеджер получает выигрыш и потерю |
| `--open-ratio`, `--won-ratio`, `--lost-ratio` | 0.45, 0.30, 0.25 | Доли должны дать единицу. Квоты целые по наибольшим остаткам, при равенстве преимущество у open, затем won |
| `--organization-name`, `--dataset-version` | DealMind Demo Academy, 1.0.0 | Название и версия входят в fingerprint. Namespace один, `dealmind-demo` |
| `--currency`, `--business-timezone` | RUB, Europe/Moscow | Основная валюта и IANA-зона календаря. Есть отдельные валютные примеры в EUR, при основной EUR — в RUB |
| `--dry-run`, `--manifest PATH` | Предпросмотр, вывод в stdout | Только для generate. Запись JSON в файл выполняется по явному пути |
| `--apply` | Выключен | Только для seed. Разрешает одну попытку загрузки в явно выбранную БД |

Локаль шаблонов — `ru_RU`, версия генератора — `1.0.0`. Если квот недостаточно для 34 контрольных сделок, восьми причин потери или покрытия менеджеров, CLI сообщает об ошибке. Пример небольшого полного набора — `generate --deals 80 --contacts 50 --managers 3`.

## Безопасная загрузка и проверка

Запускайте CLI на хосте. Нужна отдельная локальная PostgreSQL с применённой Alembic-ревизией `0002`. Для тестового кластера DealMind команды запуска и проверки приведены в руководстве API. В автоматических тестах каждый сценарий получает свою временную БД после проверки порта, тома и идентификатора кластера. [Тестовая инфраструктура](../../apps/api/README.md)

Для ручной демобазы задайте в текущем окружении все шесть значений. Выберите порт уже подготовленной базы, роль с правами чтения и вставки CRM и её пароль. Пример конфигурации — `APP_ENV=local`, `APP_DB_HOST=127.0.0.1`, `APP_DB_PORT=55433`, `APP_DB_NAME=dealmind_demo`, `APP_DB_USER=dealmind_test`. Задайте `APP_DB_PASSWORD` из локального хранилища. Seeder допускает `local` и `test`, loopback IP и имена `dealmind_demo` / `dealmind_test` с необязательным суффиксом через подчёркивание. Он сверяет фактические имя БД, роль, адрес сервера и ревизию перед вставкой. Миграции выполняются отдельно оператором.

После настройки базы загрузку можно запустить из корня репозитория.

```powershell
uv run --project .\apps\api --locked python -m dealmind.demo.cli seed --apply
```

Из `apps/api` можно проверить ревизию и повторить загрузку.

```shell
uv run --locked alembic current
uv run --locked python -m dealmind.demo.cli seed --apply
uv run --locked python -m dealmind.demo.cli seed --apply
```

Первый вызов возвращает `CREATED`. Сравните `counts`, `inserted` и `verified` для всех восьми таблиц. Второй возвращает `ALREADY_EXISTS` с нулями в `inserted`. Поле `verified` получено чтением всех сохранённых колонок в новой сессии после commit. Для работы без постоянной демобазы запустите `uv run --locked pytest -m database -k full_demo_cli_seed` на включённом тестовом кластере. Тест сам создаст и освободит временную базу.

| Код CLI | Смысл |
| ---: | --- |
| 0 | Валидный предпросмотр либо подтверждённая новая/повторная загрузка |
| 1 | Ошибка выполнения. Отдельное сообщение о сбое проверки после commit означает, что данные могли сохраниться. Повторный запуск сверит состояние |
| 2 | Ошибка аргументов, конфигурации, валидации или выбора среды/ревизии |
| 3 | CONFLICT. Обнаружен другой набор, неполная копия, изменённые строки или конфликт идентификатора. Существующие записи сохранены |

Блокировка PostgreSQL на namespace сериализует одновременные запуски. Один commit охватывает восемь таблиц. UUID организации определяется namespace, имя служит подписью. SHA-256 конфигурации записан в описание демонстрационной воронки, поэтому смена seed, версии или другого параметра обнаруживается даже при прежнем количестве строк. Для эксперимента с другой конфигурацией используйте отдельную демобазу.

## Коммерческие сценарии и воспроизводимость

В каталоге шесть образовательных программ — Python Developer, Data Analyst, AI Engineer, n8n & Business Automation, Full Stack Developer и Digital Marketing. Цены и скидки 0–25% рассчитываются через Decimal. Примеры в разных валютах используют заданные демо-цены. Для менеджеров заданы разные веса исходов, интенсивность общения, время цикла и вероятность просрочки. Такие частоты описывают тестовые данные одной школы. Цена сделки не подтверждает платёж.

В `scenario_deals` ключи SYN-001…014 ведут к конкретным сделкам — квалификация, консультация, предложение, решение, исходы, повторные обращения и покупки, пропуск, возврат, повторный вход, внутренняя заметка и поздняя регистрация. SYN-R01…R11 задают исходные факты для правил риска. Ключи B-H71/72/73, B-D13/14/15 и B-DUE-BEFORE/NOW/AFTER позволяют проверить строгие временные границы. Для просрочки используется `next_action_at < anchor`, для времени на этапе — последняя запись истории.

UUIDv5 привязаны к логическим ключам. Даты рассчитываются от anchor, случайный выбор использует собственный экземпляр Random. SHA-256 охватывает версию генератора, конфигурацию, все восемь наборов строк, включая JSONB, и ссылки сценариев. Перед хешированием строки сортируются по UUID, JSON-ключи упорядочиваются, время приводится к UTC, суммы записываются с двумя знаками. Manifest содержит агрегаты и контрольные UUID. Дамп и клиентские данные для воспроизведения не нужны. [Модель данных](../../docs/DATA_MODEL.md) · [Примеры инспекции](../../docs/DEMO_SCENARIOS.md)
